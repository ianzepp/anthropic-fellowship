### Scheduler / loops: one cadence loop, created serially (Grok Build hard rule)

Grok's session scheduler has a known failure mode: **starting loops in one parallel tool batch overwrites earlier jobs**. You often end with a single scheduler id whose prompt is whatever was specified last. Cadence then silently disappears.

The current Tugboat model runs **at most one loop**: `cadence_tick`, operator-enabled only (off by default). The retired reminder loops — `mind_wake`, `auditor_range`, `cto_range`, `polish_analyzer` — must not be armed; Auditor/CTO reacquaintance fires from Warm boot, not from a loop.

| Rule | Do | Never |
| --- | --- | --- |
| **Serial creates** | Create a loop **one invocation at a time**: call `scheduler_create` (or `/loop`) once, wait for that tool result and its **new** task id | Fire `scheduler_create` / `/loop` calls in the **same parallel tool batch** |
| **One id per loop** | `cadence_tick` gets its own scheduler job and its own id, recorded in the Mind memo | Reuse a job by updating `prompt`/`interval` to “cover” another process; arm the retired loop names |
| **Canonical payload** | Use the `$tugboat` charter-load payload for `cadence_tick` (“You are role cadence. Load charter … Tick. Review. File the opinion as mail to mind. Stop.”) | Ad-hoc prompt text that never loads the cadence charter |
| **Verify after create** | Record the returned id; `scheduler_list` and confirm exactly the expected loop | Assume a create in a batched turn produced a job |
| **Update is explicit** | Pass `task_id` only when **intentionally** changing an existing job | Pass a prior id (or a guessed id) when you meant to add a new loop |
| **Stop is per id** | `scheduler_delete` with the exact id | Delete “the” loop and hope others survive |

**Done shape when arming:** create once → store the id in the Mind memo → `scheduler_list` once and report the process name + id + interval. A memo-claimed loop absent from the scheduler is **disabled, not broken** — record it; do not recreate it without operator enablement.

**Why:** parallel create races collapse to one job, and a cadence loop with an ad-hoc prompt runs a timer but not the cadence protocol. Operator cadence depends on the one live loop being the real one.
